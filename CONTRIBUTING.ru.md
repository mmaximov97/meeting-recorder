# Как участвовать в MeetRec

Спасибо, что заглянули. MeetRec — настольное приложение для записи встреч на Tauri: ядро записи звука и детектор звонков на Rust, интерфейс на обычном HTML и JavaScript без фреймворков.

Сообщение об ошибке полезно не меньше кода. Если что-то не работает, а лезть в исходники не хочется — заведите issue: захват звука ведёт себя по-разному почти на каждой машине, и проверить все мы не можем.

## Что нужно поставить

- **Rust**, канал stable — [rustup.rs](https://rustup.rs)
- **Node.js** с npm
- Инструменты сборки системы: Xcode Command Line Tools на macOS, Visual Studio Build Tools с рабочей нагрузкой C++ на Windows

Поддерживаемые системы:

| | Версия |
|---|---|
| macOS | 11.0 и выше |
| macOS, захват системного звука | **14.4 и выше** — до неё в системе просто нет нужного механизма |
| Windows | 10 и 11 |

Строка про macOS 14.4 объясняет большинство сообщений «микрофон пишется, а собеседник нет».

## Запуск

```sh
npm install
npx tauri dev
```

Приложение забирает себе аудиоустройства и при первом запуске просит разрешение на микрофон.

## Тесты

```sh
cargo test --workspace
```

`--workspace` важен: проект состоит из двух крейтов — ядро в `src/` и интерфейс в `src-tauri/` — и без этого флага прогоняется только половина. Тесты лежат рядом с кодом, в модулях `#[cfg(test)]`, отдельной папки с тестами нет.

Тестов на JavaScript нет.

## Сборка

```sh
npx tauri build --no-bundle    # только компиляция, это же гоняет CI
npx tauri build                # установщик: NSIS на Windows, .app и .dmg на macOS
```

На macOS после сборки есть отдельная проверка:

```sh
npm run check-tap-lazy-bind
```

Она следит за тем, чтобы системный механизм захвата звука подключался лениво. Иначе приложение на macOS младше 14.4 откажется запускаться вместо того, чтобы просто работать без системного звука.

## Что где лежит

```
src/                 ядро: запись звука, детектор звонков, хранение
  capture/           macos.rs — захват через Core Audio
                     windows.rs — захват через WASAPI
  detector/          какое приложение сейчас на звонке, отдельно под каждую ОС
src-tauri/           крейт интерфейса на Tauri
  src/i18n.rs        читает strings.json для меню в строке состояния и уведомлений
ui/                  фронтенд: HTML и обычный JavaScript, без фреймворка
  i18n/strings.json  все тексты, которые видит человек
  tokens.css         цвета, отступы, типографика
.github/workflows/   CI
docs/                проектные заметки и планы
```

## Тексты в интерфейсе

**Каждая строка, которую видит человек, лежит в `ui/i18n/strings.json`.** В `.js` и `.rs` тексты не вписываются; если в пул-реквесте текст вписан прямо в код, его попросят перенести.

Файл общий для обеих половин приложения:

```json
{
  "settings": {
    "audioTitle": { "ru": "Звук", "en": "Audio" }
  }
}
```

Нужны оба языка: пропущенный перевод — это дырка в интерфейсе, а не аккуратный откат к другому языку. Читается через `window.i18n.t("settings.audioTitle")` из JavaScript и через `t("settings.audioTitle", lang)` из Rust. Rust вшивает тот же файл при компиляции, так что разъехаться они не могут.

## Код под конкретную ОС

Захват звука и детектор звонков написаны дважды, по разу на систему, в `capture/` и `detector/`. Правка в одной обычно требует зеркальной правки в другой. CI собирает под обе, так что односторонняя правка упадёт там, а не в ревью.

## Коммиты и пул-реквесты

Сообщения коммитов — по [Conventional Commits](https://www.conventionalcommits.org): `feat:`, `fix:`, `docs:`, `chore:`, `perf:`. История написана по-русски, английский так же приветствуется — пишите на том языке, на котором думаете.

Перед пул-реквестом:

- `cargo test --workspace` проходит
- `cargo fmt` прогнан
- новые тексты интерфейса лежат в `strings.json` на обоих языках

CI гоняет тесты и сборку на Windows и macOS. Обе должны быть зелёными.

Мелкие правки можно слать сразу пул-реквестом. Для чего-то большего сначала заведите issue: в этом коде есть ограничения, которые по исходникам не видны, и обидно узнать о них уже после работы.
