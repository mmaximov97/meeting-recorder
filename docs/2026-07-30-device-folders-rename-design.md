# Выбор микрофона, месячные папки и переименование записей — дизайн

**Дата:** 2026-07-30
**Статус:** утверждён, готов к плану реализации
**Предшественник:** `<vault>/Brainstorming/Открытый аналог Granola/2026-07-17-meeting-recorder-mvp-design.md` (спека MVP)

## Зачем

Запись встречи от 30.07 показала, что микрофонная дорожка тише системной на 36 дБ по RMS. Причина — `build_capture` берёт `host.default_input_device()`, то есть системный дефолт; на этой машине это дальнопольный `Microphone Array (Intel SST)`, тогда как говорят в `Headset (Boss Bose)`. Whisper выбрасывает такую дорожку по VAD как тишину, и в транскрипте реплики владельца превращаются в обрывки. Отказ при этом **маскируется под успех**: файл существует, весит сколько положено, открывается и играет — просто в нём почти нет голоса.

Отсюда три правки, две из которых про гигиену каталога:

1. **Выбор устройства микрофона** — чтобы писать в тот микрофон, в который говорят.
2. **Месячные папки** — в корне `C:\Users\<username>\Recordings` уже ~30 файлов вперемешку с `.transcript`-папками.
3. **Переименование записей** — `2026-07-30_13-03_chrome` не говорит ничего о том, что это за встреча.

Плюс контроль уровня: сам по себе выбор устройства не доказывает, что выбранное устройство слышит владельца.

## Что НЕ входит

- Выбор устройства вывода (источника loopback). Собеседников слушают через тот же выход, на который идёт звук, поэтому системного дефолта достаточно. Отдельный выбор потребовал бы поднимать тихий render-поток ровно на выбранном выходе — цена не оправдана сценарием «пишу с колонок, слушаю в наушниках», которого нет.
- Свободное переименование целиком. Дата-время в имени — несущая конструкция: по ней идёт сортировка списка, группировка пары дорожек и выбор месячной папки.
- Код миграции старых записей внутри приложения. Разложить существующие файлы — одноразовая операция, см. «Миграция».
- Ручная раскладка записей по тематическим папкам. Раскладка автоматическая по дате.

## Решения и обоснования

### Границы: ядро не знает про настройки на диске

Ядро (`meeting_recorder`) принимает выбор устройства как значение и ничего не сериализует. GUI отвечает за то, где это значение живёт между запусками. Причина — та же, по которой ядро уже отделено от Tauri: `App` тестируется без COM, без устройств и без файловой системы, и добавление в него чтения конфига эту способность отняло бы.

```rust
// src/capture/mod.rs — ядро
pub enum DeviceChoice { Default, Id(String) }
pub struct InputDevice { pub id: String, pub name: String }
pub fn list_input_devices() -> Result<Vec<InputDevice>, CaptureError>;
```

```rust
// src-tauri/src/config.rs — GUI
#[derive(Serialize, Deserialize, Default, Clone)]
pub struct Config {
    /// Идентификатор эндпоинта. None = системный дефолт.
    pub mic_device_id: Option<String>,
    /// Имя на момент выбора — только для показа. Матчинг по нему не идёт.
    pub mic_device_name: Option<String>,
}
```

**Хранилище:** `app.path().app_config_dir()/config.json`. Путь даёт сам Tauri, новых зависимостей не появляется (`serde` уже в дереве через Tauri). Отвергнуто: `tauri-plugin-store` — плагин и права в capabilities ради одного поля; файл рядом с exe — `cargo clean` сносит `target/release/`, и настройка исчезает молча.

**Битый или нечитаемый конфиг не роняет приложение:** берётся `Config::default()`, причина уходит в UI обычной (не фатальной) ошибкой. Потерять настройку неприятно; не записать встречу — хуже.

### Разрешение устройства и фолбэк

```rust
pub struct Resolved { pub device: cpal::Device, pub fell_back_from: Option<String> }
pub fn resolve_input(choice: &DeviceChoice) -> Result<Resolved, CaptureError>;
```

`Id(id)` ищется по идентификатору эндпоинта среди `host.input_devices()`. Не нашлось — берётся системный дефолт, а в `fell_back_from` кладётся искомый идентификатор.

**Идентификатор, а не имя.** Первая редакция этой спеки утверждала, что «cpal не даёт стабильных идентификаторов, имя — единственное, что есть». Это оказалось неверно, и обнаружилось на ревью Task 2. В cpal 0.18.1 есть `DeviceTrait::id() -> Result<DeviceId, Error>`; на Windows он возвращает `IMMDevice::GetId()` — эндпоинт-идентификатор WASAPI, а докблок самого типа предписывает ровно наш сценарий: «Application code should obtain `DeviceId` values through `DeviceTrait::id` and persist them via `Display`/`FromStr`».

Разница не косметическая. Имя ломается в двух реальных случаях — устройство переименовали в настройках Windows, или два эндпоинта названы одинаково, — и ломается тихо, откатом на системный дефолт. То есть даёт ровно тот отказ, ради устранения которого вся эта работа и затеяна.

Имя при этом продолжает храниться, но **только для показа**: когда выбранного устройства нет в системе, выпадашка обязана сказать «Headset (Boss Bose) (сейчас недоступен)», а не показать пользователю строку вида `{0.0.1.00000000}.{guid}`. Матчинг по имени не идёт никогда — это единственный способ не получить обратно ту же хрупкость через чёрный ход.

Ядро при этом знает только идентификаторы: `fell_back_from` несёт наверх именно его, а превращает его в человеческое имя GUI, у которого есть конфиг с запомненным именем. Читается имя через `Device::description()?.name()` — метода `Device::name()` в 0.18.1 нет.

Матчинг вынесен в чистую функцию:

```rust
fn pick(names: &[String], choice: &DeviceChoice) -> Option<usize>;
```

Это единственная часть разрешения устройства, которую можно проверить без железа, и единственная, которую можно сломать незаметно: перепутанный порядок аргументов или `contains` вместо равенства дадут не ошибку, а тихо не то устройство — ровно тот класс отказа, из-за которого эта спека и появилась.

**Поведение при пропаже устройства — фолбэк с громким предупреждением**, а не отказ писать. Цена ошибки несимметрична: испорченная дорожка чинится вторым дублем или усилением, потерянная встреча не чинится ничем.

Как предупреждение доходит до глаз: `CpalAudio` запоминает последний `fell_back_from`, `App` отдаёт его через `device_warning()`, цикл в `audio.rs` сравнивает со своей копией в `Status` и при изменении шлёт событие `warning` в webview плюс системный тост. Предупреждение висит до конца записи, а не гаснет через несколько секунд: смысл в том, чтобы владелец узнал это во время встречи, а не через день на транскрипте.

### Разделение `build_capture` на две функции

Сейчас это одна функция с тремя `match source` внутри (устройство, конфиг, комментарий), и сам `Source` существует главным образом чтобы эти матчи развести. Выбор устройства касается только микрофона, значит добавился бы четвёртый матч с `Option` в одной ветке и `unreachable` в другой.

```rust
pub fn build_mic_capture(choice: &DeviceChoice, sink: Sender<Vec<i16>>) -> Result<PendingCapture, CaptureError>;
pub fn build_loopback_capture(sink: Sender<Vec<i16>>) -> Result<PendingCapture, CaptureError>;
```

Матчи исчезают, `Source` остаётся только для сообщений об ошибках. Это правка внутри того кода, который и так меняется, а не отдельный рефакторинг.

### Режим проверки микрофона вместо постоянного индикатора

Спека MVP содержит жёсткий инвариант: потоки захвата открываются только на детекте или ручном старте, чтобы индикатор микрофона в Windows горел ровно тогда, когда приложение слушает. Он помечен как «соблазн открыть один раз и держать — реален, не делать».

Постоянный индикатор уровня в `Idle` этот инвариант нарушает напрямую. Поэтому вместо него — явный режим проверки:

```rust
impl App { pub fn set_monitor(&mut self, on: bool); }
```

- В `Idle` включение открывает те же потоки через `open()`, но **не пишет ни в кольцо, ни в файл** — только считает пики.
- Выключение закрывает потоки **только если машина всё ещё в `Idle`**. Если за время проверки пришёл детект встречи, потоки уже принадлежат записи, и гасить их нельзя.
- Авто-выключение через 60 секунд, чтобы забытая проверка не держала микрофон бесконечно. Таймер считает цикл в `audio.rs` (он и так тикает раз в 200 мс), а не webview: окно можно закрыть, и тогда выключать проверку стало бы некому.

Инвариант сохраняется по смыслу, а не только по букве: микрофон открыт, потому что пользователь явно попросил его послушать, и индикатор Windows при этом честно горит.

Детектор увидит нашу собственную mic-сессию, но `poll_to_event` уже фильтрует свой pid — дыра закрыта заранее, дописывать ничего не нужно.

**Уровень:**

```rust
pub struct Levels { pub mic: f32, pub system: f32 }   // пик за последний тик, 0..1
impl App { pub fn levels(&self) -> Levels; }
```

Считается в `pump_audio` по уже дренированным чанкам — данные и так проходят через эту функцию, дополнительной работы нет. Затухание между тиками, чтобы полоска не дёргалась.

### Месячные папки

```rust
// src/storage.rs
pub fn month_dir(root: &Path, started: DateTime<Local>) -> PathBuf;   // root/2026-07
```

`App` получает корень, а не готовый каталог, и считает месячную папку на старте записи. `WavSink::create` уже вызывает `create_dir_all`, поэтому создание папки не требует отдельного шага. `free_name_pair` ищет свободное имя внутри месячной папки — правило подбора не меняется, меняется каталог.

Гранулярность `YYYY-MM`, а не `YYYY-MM-DD`: при 1–3 встречах в день это 30–60 файлов на папку, что читаемо, тогда как папка на каждый день дала бы сотни папок по паре файлов.

Хардкод пути живёт в **двух** местах — `src-tauri/src/main.rs:24` и `src/main.rs`. Оба переезжают на корень + `month_dir`. Разъедься они, GUI перестал бы видеть записи, сделанные консольным бинарём, — тем самым, которым отлаживают то же ядро.

### Имена и переименование

Формат остаётся `YYYY-MM-DD_HH-MM_<хвост>[_N].{mic|system}.wav`. Префикс — ровно первые 17 символов, фиксированная ширина, парсится однозначно.

```rust
pub fn split_name(base: &str) -> Option<(String, String)>;        // ("2026-07-30_13-03_", "chrome")
pub fn rename_tail(base: &str, new_tail: &str) -> Option<String>;
```

`None` возвращается в двух случаях: база не начинается с корректного 17-символьного префикса (чужой файл в каталоге) или очищенный хвост оказался пустым. Пустой хвост — именно ошибка, а не подстановка `unknown`: при автоматическом именовании источник берётся из имени процесса и подставить туда нечего, а здесь человек стёр поле и должен это увидеть.

Хвост чистится существующей `sanitize_source`: она уже делает ровно нужное — сохраняет юникодные буквы (кириллические хвосты реальны), заменяет разделители дефисом, схлопывает повторы, режет по 100 символам по границе символа. Второй санитайзер не пишется.

**Переименовываются три сущности:** `<base>.mic.wav`, `<base>.system.wav` и `<base>.transcript/`, если она есть. Последняя — это выход скрипта `ailab-transcribe`, который кладёт результат рядом с записью; оставить её со старым именем значит развязать транскрипт и запись.

Порядок: сначала проверить, что **все** целевые имена свободны, потом переименовывать по очереди; при отказе на середине — откатить уже сделанное. Это не транзакция (три `fs::rename` в одной папке), но и не молчаливая половина.

**Занятое имя — ошибка, а не автоподбор `_N`.** Автоподбор уместен там, где имя выбирает машина (`free_name_pair` при старте записи); здесь имя выбрал человек, и подмена за спиной означала бы, что запись потом ищут не там, куда её положили.

### Список записей

`list_recordings` обходит корень плюс подпапки первого уровня с именем вида `\d{4}-\d{2}`. Не произвольная глубина: предсказуемо и не засасывает чужое дерево, если рядом окажется что-то постороннее. Файлы, оставшиеся в корне, продолжают показываться — но только если они пара дорожек: `group_recordings` и сейчас пропускает всё, что не `*.mic.wav` / `*.system.wav`, и это не меняется. Положенный вручную `2026-07-30_pms-demo-monastyrnyi.mp4` в списке не появится ни до правки, ни после — приложение показывает свои записи, а не содержимое каталога.

`Recording` получает два поля: `folder: Option<String>` (None = корень) и `imbalance_db: Option<f32>`.

Сортировка не меняется: base начинается с `YYYY-MM-DD_HH-MM`, поэтому лексикографический порядок и есть хронологический — независимо от того, из какой папки пришёл файл.

### Пометка «микрофон тише системы»

```rust
// src-tauri/src/imbalance.rs
pub fn sampled_rms_dbfs(path: &Path, windows: usize) -> io::Result<f32>;
pub fn imbalance(mic_dbfs: f32, sys_dbfs: f32) -> Option<f32>;   // Some(diff) при mic тише на > 20 дБ
```

Модуль называется `imbalance`, а не `levels`, чтобы не путался с `App::levels()`: тот отдаёт живой пик по открытым потокам, этот считает RMS по готовому файлу. Разные величины, разные источники, разное время жизни.

**RMS, а не пик.** У записи 30.07 пики разошлись на 16 дБ (в пределах нормального), а RMS — на 36. Пик ловит стук по столу; RMS ловит «микрофон стоит не там». Порог 20 дБ выбран между этими числами с запасом от нормальной разницы близких уровней (до ~10 дБ).

**Ленивый расчёт по разреженной выборке**, а не сайдкар-файл на финализации: он покрывает и ~30 уже лежащих файлов, ничего не хранит и не может устареть. 200 окон по 4096 сэмплов равномерно по файлу через `WavReader::seek` — для 38-минутной записи это ~1.6 МБ чтения вместо 73 МБ. Файл короче, чем `windows * 4096` сэмплов, читается целиком: выборка вырождается в полный проход, а не в ошибку.

Кеш — `Mutex<HashMap<(PathBuf, u64, SystemTime), f32>>` в состоянии Tauri. Ключ включает размер и время модификации, поэтому заменённый или дописанный файл пересчитывается сам, а список, обновляющийся на каждый фокус окна, не перечитывает диск заново.

Обе дорожки тихие (запись в тишину) — пометки нет: разницы нет, и предупреждать не о чем.

### Миграция

Существующие файлы и `.transcript`-папки раскладываются по `YYYY-MM/` **одноразовым скриптом при внедрении**, а не кодом в приложении. Код миграции работал бы вечно ради задачи, которая случается один раз, и при каждом запуске молча двигал бы пользовательские файлы.

Раскладка идёт по дате в начале имени — `^\d{4}-\d{2}-\d{2}`, без требования времени. Этого достаточно, чтобы переехало и то, что положено руками: `2026-07-30_pms-demo-monastyrnyi.mp4` вместе со своей `.transcript`-папкой уедет в `2026-07/` наравне с записями приложения. В корне остаётся только то, у чего даты в имени нет вообще.

Требование к скрипту одно: **пара дорожек и её `.transcript` не должны разъехаться по разным папкам**. Поэтому перенос идёт группой по общей основе имени, а не пофайлово.

### Внешняя зависимость: скилл `meeting-to-vault`

Скилл описывает записи как лежащие плоско в `C:\Users\<username>\Recordings` и ищет пары `*.mic.wav` / `*.system.wav` там. После перехода на месячные папки его надо обновить, иначе следующая встреча просто не найдётся. Это часть объёма работ, а не следствие.

Заодно туда же уходит рецепт выравнивания уровней при миксовании (`volume=16dB` на mic перед `amix`) — он остаётся нужным для всех записей, сделанных до этой правки.

## Отказы

Ни один не роняет запись.

| Отказ | Поведение |
|---|---|
| Конфиг не читается или битый | `Config::default()`, причина в UI обычной ошибкой |
| Устройства не перечисляются | Выпадашка пуста, запись идёт на системном дефолте |
| Выбранное устройство исчезло | Фолбэк на дефолт + предупреждение до конца записи |
| Переименование: имя занято | Ошибка в UI, на диске ничего не изменилось |
| Переименование: файл держит другой процесс | Откат уже переименованного, ошибка в UI |
| Уровни не считаются (битый или обрезанный WAV) | Пометки просто нет — это не ошибка |
| Проверка микрофона не открыла поток | Ошибка в UI, состояние машины не меняется |

## Тесты

Все без железа, встречи и микрофона.

- `pick` — точное совпадение, отсутствие, дубликаты имён, `Default`.
- `month_dir` — граница месяца, локальная зона.
- `split_name` / `rename_tail` — префикс фиксированной ширины, суффикс `_N`, кириллический хвост, пустой хвост (ошибка), обрезка длинного.
- `rename_recording` на `ScratchDir` — три сущности переезжают вместе; откат при коллизии; отсутствующая `.transcript` не ломает переименование.
- `group_recordings` — записи из корня и из подпапок в одном списке, порядок «свежее сверху» независимо от папки.
- `imbalance` — порог сверху и снизу, равные уровни, обе дорожки тихие (ложной пометки быть не должно).
- `sampled_rms_dbfs` — на сгенерированном WAV с известной амплитудой; отдельно на файле короче окна выборки.
- Проводка `set_monitor`: выключение в `Idle` закрывает потоки, выключение при пришедшем детекте — не закрывает.

## Порядок работ

От того, что чинит боль, к тому, что её предотвращает:

1. Конфиг, выпадашка устройств, фолбэк с предупреждением, разделение `build_capture`.
2. Месячные папки; сюда же разовая миграция и обновление скилла `meeting-to-vault`.
3. Переименование записей.
4. Режим проверки микрофона, индикатор уровня, пометка дисбаланса в списке.

Первый пункт самодостаточен: после него запись идёт в правильный микрофон, даже если остальное не сделано.
