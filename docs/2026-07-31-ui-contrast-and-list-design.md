# Контраст выпадашки и читаемость списка записей — дизайн

**Дата:** 2026-07-31
**Статус:** утверждён, готов к плану реализации
**Предшественник:** `docs/2026-07-30-device-folders-rename-design.md`

## Зачем

Первый живой запуск окна после вливания ветки выбора микрофона показал два дефекта и одну проблему читаемости.

**Выпадашка нечитаема.** У `select` стоит `background: transparent` (`ui/index.html:106`), а текст — `color: var(--fg)`, то есть в тёмной теме почти белый. Нативный попап WebView2 при прозрачном фоне рисует себя светлым, буквы остаются белыми, и невыбранные пункты («Microphone Array…», «Headset (Boss Bose)») сливаются с фоном. Выбранный пункт читается только за счёт собственной подсветки.

**Кнопка «Проверить» вытолкнута за край окна.** Она есть в разметке (`ui/index.html:211`) рядом с выпадашкой, но при штатной ширине окна её не видно — вместо неё внизу горизонтальная полоса прокрутки. У флекс-элементов `min-width: auto`, поэтому самое длинное имя устройства (`Microphone Array (Intel® Smart Sound Technology (Intel® SST))`) не даёт выпадашке сжаться, строка распирает окно, кнопка уезжает вправо.

Это не косметика: проверка микрофона недоступна при ширине окна по умолчанию, а ради неё делалась последняя треть предыдущей работы. Тот же класс бага уже чинили в списке записей через `min-width: 0` на `.grow` — здесь его просто не поставили.

**Список тяжело читается.** Мета-строка переносится на вторую строку, а «Переименовать» повторяется шестью одинаковыми синими прямоугольниками и перетягивает внимание с самих записей.

## Что НЕ входит

- Пересборка композиции окна. Порядок блоков, набор элементов и поведение остаются как есть.
- Свой дропдаун на `div` вместо нативного `select`.
- Тесты на фронтенде. Инфраструктуры для них в проекте нет, и заводить её ради одной строки форматирования — плохой размен.

## Решения и обоснования

### Контраст: чинить цвета, а не заменять контрол

```css
select {
  min-width: 0;
  background: var(--bg);
  color: var(--fg);
}
option { background: var(--bg); color: var(--fg); }
```

Нативный попап остаётся нативным: клавиатурная навигация, скролл, поиск по первой букве и поведение при выходе за край экрана работают сами. Свой дропдаун на `div` дал бы полный контроль над видом, но потребовал бы заново сделать фокус, стрелки, Escape и доступность — ради одной проблемы с цветом это несоразмерно.

`option` красится явно, а не полагается на наследование: попап рисует не страница, а браузер, и наследование в него доходит непоследовательно между версиями WebView2.

### `min-width: 0` — причина, а не симптом

Горизонтальную прокрутку можно было бы убрать через `body { overflow-x: hidden }`, но это спрятало бы кнопку насовсем вместо того, чтобы вернуть её в окно. `min-width: 0` снимает запрет на сжатие флекс-элемента: выпадашка ужимается по доступному месту и сама обрезает длинное имя многоточием, кнопка остаётся на своём месте.

Тем же движением `.name` в списке получает `overflow: hidden; text-overflow: ellipsis; white-space: nowrap` — после переименования длинное имя распёрло бы строку ровно так же.

### Папка в мете — только когда она аномальна

Сейчас в мете всегда пишется `2026-07`, хотя это буквально первые семь символов имени, стоящего строкой выше. Информации ноль, место занято.

Новое правило: папка показывается, **только если не совпадает с датой в имени**.

| Состояние | Что в мете |
|---|---|
| `folder` совпадает с `name[0..7]` | ничего |
| `folder == null` (запись в корне) | `в корне` |
| `folder` не совпадает с датой (двигали руками) | значение `folder` |

Так пометка означает «здесь что-то не так» вместо того, чтобы быть всегда. Убрать папку совсем нельзя: тогда пропал бы единственный признак записи, оставшейся в корне после незавершённой миграции.

### Кнопка переименования — тихая, но на месте

Убирать кнопку и переименовывать по двойному клику — соблазнительно и неправильно: пропадает и обнаруживаемость, и доступ с клавиатуры. Прятать её до наведения — то же самое для тех, кто ходит табом.

Поэтому кнопка остаётся всегда, но по умолчанию рисуется без рамки, цветом `--muted`; рамка и акцентный цвет появляются на `:hover` и `:focus-visible`. Шесть одинаковых синих прямоугольников перестают конкурировать с содержимым, но контрол никуда не девается.

### Размер файла — без ложной точности

`139.2 МБ` — десятая доля мегабайта не значит ничего при таком масштабе, а `1720.2 МБ` ещё и плохо читается. Мегабайты округляются до целого, а от 1024 МБ показываются гигабайты с одним знаком: `1.7 ГБ`. Ступени ниже мегабайта (`Б`, `КБ`) остаются как есть — там точность как раз имеет смысл, и трогать их незачем.

### `--warn` в палитру

Цвет предупреждения `#d0761a` захардкожен в двух местах (`#devwarn` и `.warn`). Это отложенная находка из журнала ревью предыдущей ветки; раз CSS и так открыт, дешевле закрыть сейчас, чем заводить третье вхождение при следующей правке.

## Итоговый вид строки записи

| Было | Стало |
|---|---|
| `2026-07 · mic + system · 139.2 МБ · микрофон тише системы на 37 дБ` | `mic + system · 139 МБ · микрофон тише на 37 дБ` |
| `2026-07 · mic + system · 1720.2 МБ` | `mic + system · 1.7 ГБ` |
| `mic · 6.7 МБ · дорожка отсутствует` | `в корне · mic · 6 МБ · дорожка отсутствует` |

## Отказы

Отдельных путей отказа задача не добавляет: меняются только правила отрисовки уже полученных данных. Единственное поведение, которое стоит назвать явно, — запись с неразбираемым именем (не начинается с даты): сравнение папки с `name[0..7]` просто не совпадёт, и папка покажется как аномалия. Это верно по смыслу — такая запись действительно требует внимания.

## Проверка

Юнит-тестов здесь не будет (см. «Что НЕ входит»). Проверяется глазами, три пункта:

1. Раскрыть выпадашку — все три пункта читаемы в тёмной теме.
2. Кнопка «Проверить» видна при ширине окна по умолчанию, горизонтальной прокрутки внизу нет.
3. В списке: у июльских записей стоит пометка перекоса, папка не показывается; у записи, лежащей в корне (если такая появится), стоит `в корне`.
