# Контраст выпадашки и читаемость списка — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Сделать выпадашку микрофона читаемой в тёмной теме, вернуть вытолкнутую за край окна кнопку «Проверить» и разгрузить строку записи в списке.

**Architecture:** Правки только в двух файлах фронтенда — `ui/index.html` (стили) и `ui/main.js` (сборка строки записи). Rust не трогается вообще: данные приходят те же, меняются правила их отрисовки.

**Tech Stack:** Ванильный JS + CSS без сборщика, WebView2 под Tauri v2.

**Спека:** `docs/2026-07-31-ui-contrast-and-list-design.md`. Читать до начала — здесь только «как», обоснования «почему» там.

## Global Constraints

- **Таргет только `x86_64-pc-windows-msvc`.** Сборка — только Windows-тулчейном через интероп: `cargo.exe build --release -p meeting-recorder-gui`. Обычный `cargo` соберёт Linux-бинарь.
- **Код живёт на Windows-диске:** `/mnt/c/Users/<you>/Projects/meeting-recorder`.
- **Комментарии и сообщения коммитов — на русском**, как во всём проекте. Тексты интерфейса — тоже на русском.
- **Фронтенд — ванильный JS без сборщика.** Никаких npm-пакетов, импортов и фреймворков.
- **Фронтенд намеренно тонкий:** состояние машины в нём не дублируется, он только рисует то, что пришло с бэкенда.
- **Ноль предупреждений компилятора** — дисциплина проекта.
- **Автоматических тестов на фронтенде в проекте нет и в этой работе не заводится.** Критерий готовности задачи — успешная релизная сборка; правильность вида проверяет человек глазами по чек-листу в конце плана.
- **Не убивать чужие процессы.** `meeting-recorder-gui.exe` — фоновый демон пользователя; если релизная сборка упрётся в `Access is denied`, остановиться и сообщить, а не обходить блокировку.
- **Каталог `C:\Users\<you>\Recordings` не трогать** — там настоящие записи встреч.

В `ui/index.html` заменить правило `select` целиком:

```css
      select {
        font: inherit;
        flex: 1;

           длинное имя устройства («Microphone Array (Intel® Smart Sound
           Technology (Intel® SST))») распирало строку, кнопка «Проверить»
           уезжала за край окна, а внизу появлялась горизонтальная прокрутка.
```

### Task 2: Разгрузить строку записи

**Files:**
- Modify: `ui/index.html` (переменная `--warn` в `:root`, правила `#devwarn`, `.warn`, `.rename`)
- Modify: `ui/main.js` (функция `размер`, функция `обновить_список`); Create: функция `папка_аномальна`

**Interfaces:**
- Consumes: поля записи из команды `list_recordings` — `name: String`, `folder: String | null`, `mic: bool`, `system: bool`, `size: u64`, `imbalance_db: number | undefined`
- Produces: `папка_аномальна(запись) -> string | null`

- [ ] **Step 1: Завести переменную предупреждающего цвета**

В `ui/index.html`, в блок `:root`, последней строкой перед закрывающей скобкой:

```css
        --warn: #d0761a;
```

В тёмный блок `@media (prefers-color-scheme: dark)` ничего не добавлять: оранжевый одинаково читается на обоих фонах, и второе объявление только создало бы место для расхождения.

- [ ] **Step 2: Убрать оба хардкода цвета**

Заменить правило `#devwarn`:

```css
      #devwarn {
        display: none;
        border: 1px solid var(--warn);
        border-radius: 8px;
        padding: 10px 12px;
        margin-bottom: 12px;
        color: var(--warn);
      }
```

и правило `.warn`:

```css
      .warn {
        color: var(--warn);
      }
```

- [ ] **Step 3: Сделать кнопку переименования тихой**

Заменить правило `.rename`:

```css
      /* Кнопка есть в каждой строке, поэтому по умолчанию она молчит: шесть
         одинаковых акцентных прямоугольников перетягивали внимание с самих
         записей. Прятать её до наведения нельзя — потеряется доступ с
         клавиатуры, поэтому она остаётся на месте, но проявляется по фокусу. */
      .rename {
        padding: 4px 8px;
        font-size: 12px;
        border-color: transparent;
        color: var(--muted);
      }
      .rename:hover,
      .rename:focus-visible {
        border-color: var(--accent);
        color: var(--fg);
      }
```

- [ ] **Step 4: Показывать папку только когда она противоречит имени**

В `ui/main.js`, сразу после функции `размер`, добавить:

```js
// Папка выводится в строке записи, только если противоречит дате в имени.
// При совпадении она буквально повторяет первые семь символов имени, стоящего
// строкой выше, — информации ноль, место занято. Несовпадение же означает, что
// запись лежит не там: осталась в корне после незавершённой миграции или её
// двигали руками. Тогда это единственный признак, что стоит присмотреться.
function папка_аномальна(запись) {
  if (запись.folder == null) return "в корне";
  return запись.folder === запись.name.slice(0, 7) ? null : запись.folder;
}
```

- [ ] **Step 5: Округлить размер и добавить гигабайты**

Заменить функцию `размер` целиком:

```js
function размер(байты) {
  if (байты < 1024) return `${байты} Б`;
  const кб = байты / 1024;
  if (кб < 1024) return `${кб.toFixed(0)} КБ`;
  const мб = кб / 1024;
  // Десятая доля мегабайта при таком масштабе не значит ничего, а «1720.2 МБ»
  // ещё и плохо читается. От гигабайта один знак возвращаем — там он различим.
  return мб < 1024 ? `${Math.round(мб)} МБ` : `${(мб / 1024).toFixed(1)} ГБ`;
}
```

- [ ] **Step 6: Собрать строку записи по-новому**

В `ui/main.js`, в функции `обновить_список`, заменить тело цикла `for (const з of записи)` от создания `имя` до строки с `imbalance_db` включительно:

```js
      const имя = document.createElement("div");
      имя.className = "name";
      имя.textContent = з.name;
      // Имя обрезается многоточием (см. `.name` в стилях) — полное отдаём
      // подсказкой, иначе после переименования его будет не прочитать.
      имя.title = з.name;
      const мета = document.createElement("div");
      мета.className = "meta";
      // Отсутствие дорожки — не косметика: пара mic+system и есть запись.
      const дорожки = [з.mic ? "mic" : null, з.system ? "system" : null].filter(Boolean);
      const части = [дорожки.join(" + "), размер(з.size)];
      const аномалия = папка_аномальна(з);
      if (аномалия) части.unshift(аномалия);
      мета.textContent = части.join(" · ");
      if (!з.mic || !з.system) {
        мета.classList.add("warn");
        мета.textContent += " · дорожка отсутствует";
      }
      if (з.imbalance_db != null) {
        мета.classList.add("warn");
        мета.textContent += ` · микрофон тише на ${Math.round(з.imbalance_db)} дБ`;
      }
```

Остальная часть цикла (`колонка`, `кнопка`, `li.append`) не меняется.

## Проверка человеком

Автотестов на фронтенде нет, поэтому вид проверяется глазами. Запустить `target\release\meeting-recorder-gui.exe` (или ярлык «Запись встреч») и пройти пять пунктов:

1. **Выпадашка.** Раскрыть список микрофонов в тёмной теме — все пункты читаемы, включая невыбранные.
2. **Кнопка «Проверить».** Видна справа от выпадашки при ширине окна по умолчанию; горизонтальной полосы прокрутки внизу нет.
3. **Длинное имя устройства.** Выбрать `Microphone Array (Intel® Smart Sound Technology (Intel® SST))` — имя обрезается многоточием, а не распирает окно.
4. **Список записей.** У июльских записей стоит пометка перекоса и НЕ показывается папка `2026-07`; размеры без десятых долей, большие — в гигабайтах. Кнопки «Переименовать» приглушены и проявляются при наведении.
5. **Клавиатура.** Пройти табом по строкам списка — кнопка переименования получает видимую рамку по фокусу, то есть остаётся доступной без мыши.

Если запись, оставшаяся в корне, в каталоге отсутствует (миграция прошла целиком), пункт про `в корне` проверить нечем — это нормально, поведение видно из кода.
