# Дизайн-канон «Записи встреч»

Версия приложения — 0.2.0. Канон писался до кода (на 0.1.6) и сверен с ним
заново перед выпуском: там, где экран и канон разошлись, правым признавался тот,
за кем стоит причина, — и правился второй. Что осталось нерешённым, лежит в
разделе 6, а не между строк.
Эталонный экран — [`docs/mockups/layout-a.html`](mockups/layout-a.html).
Откройте его в браузере: слева панель состояний, справа окно 460×640 в тех же
размерах, что настоящее.

Этот файл — единственный источник правды по внешнему виду. Если что-то не описано
здесь, смотрите макет; если и в макете нет — решение принимается один раз и
дописывается сюда, а не угадывается заново в каждой ветке.

## Рамки, которые не обсуждаются

- Ванильные HTML/CSS/JS. Ни Vite, ни React, ни Tailwind, ни npm-пакетов.
- Фронтенд — два файла: `ui/index.html` (стили внутри `<style>`) и `ui/main.js`.
- CSP: `default-src 'self'; style-src 'self' 'unsafe-inline'`. Внешние шрифты, CDN
  и иконочные библиотеки не загрузятся. **Иконки — только инлайновым SVG.**
- Окно 460×640, приложение живёт в трее. Горизонтальной прокрутки не бывает
  никогда: у каждого гибкого элемента, который может распереть строку, стоит
  `min-width: 0`.

# 1. Токены

## 1.1 Цвета

**Цвета поменялись, и тем теперь две.** Токены живут в одном файле —
[`ui/tokens.css`](../ui/tokens.css) — и подключаются в `ui/index.html` и
`ui/ask.html` через `<link>` перед их собственными `<style>`. Схема Tokyo
Night, которая стояла здесь раньше, снята полностью; обоснование прежней
палитры (`docs/2026-08-03-tokyo-night-palette-design.md`) больше не действует.

Светлая тема — по умолчанию, тёмная включается системной
`prefers-color-scheme: dark`. Переключателя темы в интерфейсе пока нет
(раздел 6), но крючок под него уже готов: атрибут `data-theme="light"` или
`data-theme="dark"` на `<html>`, проставленный руками, переопределяет
системную тему.

```css
/* ui/tokens.css — сокращённо, полный файл со всеми комментариями там же */
:root {
  color-scheme: light dark;
  --bg: #f4f6f8;      --card: #ffffff;   --fg: #1d2126;    --muted: #626b76;
  --line: #dde1e7;    --line-strong: #848c99;
  --accent: #2b3138;  --on-accent: #ffffff;
  --warn: #8a6d1f;    --error: #b04a4a;  --good: #4f7048;
  --hover: rgba(43, 49, 56, .06);
  --shadow-menu: 0 12px 28px rgba(30, 35, 45, .16);
}
@media (prefers-color-scheme: dark) {
  :root {
    --bg: #101215;     --card: #171a1f;    --fg: #dfe4ea;   --muted: #868e99;
    --line: #24282e;   --line-strong: #616b79;
    --accent: #d7dee6; --on-accent: #101215;
    --warn: #c2a35f;   --error: #d07a7a;   --good: #86a37f;
    --hover: rgba(215, 222, 230, .07);
    --shadow-menu: 0 12px 32px rgba(0, 0, 0, .6);
  }
}
/* :root[data-theme="light"] и :root[data-theme="dark"] повторяют то же самое
   для ручного переопределения — см. файл целиком. */
```

### `--line-strong` — новый токен

Обычная `--line` даёт примерно 1,2:1 к фону — как разделитель (граница
карточки, строка списка, `.menu .sep`) это верно, но та же линия на границе
элемента управления не видна: кнопку или поле без подписи не отличить от
пустого места. `--line-strong` даёт заметно больший контраст и ставится
**только** на то, что можно нажать или куда можно печатать: `input`, `select`,
`button.sec`. Разделители и рамки карточек остаются на `--line`.

### Ещё две переменные сверх основной палитры

| Токен | Значение (светлая / тёмная) | Для чего |
|---|---|---|
| `--hover` | `rgba(43,49,56,.06)` / `rgba(215,222,230,.07)` | Подсветка строки и пункта меню под курсором и под фокусом. Полупрозрачный оттенок текста, а не отдельный цвет — ложится на любой фон |
| `--card` | `#ffffff` / `#171a1f` | Фон приподнятой поверхности: панель «идёт запись», меню, аватар записи |
| `--shadow-menu` | `0 12px 28px rgba(30,35,45,.16)` / `0 12px 32px rgba(0,0,0,.6)` | Тень меню «⋯» |

### Токены всплывашки — отдельный набор

Всплывашка «Записать встречу?» (2.8) **не красится токенами приложения** —
это отдельное окно поверх чужих окон, оно читается как системное
уведомление и не должно менять цвет вместе с `--accent`. У неё свой набор,
тоже в `ui/tokens.css`, тоже завязанный на тему системы:

`--toast-bg`, `--toast-fg`, `--toast-fg-dim`, `--toast-surface`,
`--toast-surface-hover`, `--toast-life`, `--toast-life-hover`,
`--toast-shadow`. Значения — в файле токенов; светлая копирует прежний
плотный тёмный вид не полностью — это отдельная, более светлая, системная
плашка.

### Кто за что отвечает

| Цвет | Где применяется | Где НЕ применяется |
|---|---|---|
| `--fg` | основной текст, название записи, пункты меню, пиковый маркер метра | мета-строка |
| `--muted` | мета-строка, время, заголовки дней, подписи, иконки в покое, подвал | текст, который нужно прочитать обязательно |
| `--accent` | главная кнопка, контур фокуса, полоска прогресса, ссылка под наведением | фон предупреждений |
| `--warn` | «работает, но не полностью»: баннер, карточка предупреждения, средняя зона метра | ошибки, после которых ничего не осталось |
| `--error` | «не получилось»: точка идущей записи, красная зона метра, текст ошибки | предупреждения, которые не сломали запись |
| `--good` | нормальная зона метра, «✓ Сохранено» | что-либо ещё |
| `--line` | разделители, рамки карточек, дорожка метра и прогресса, `.menu .sep` | границы кнопок и полей ввода |
| `--line-strong` | границы `input`, `select`, `button.sec` — того, что можно нажать или куда можно печатать | разделители, рамки карточек |

## 1.2 Отступы

Шкала — **4 / 8 / 12 / 16 / 24**. Промежуточных значений нет; если кажется, что
нужно 10 — берите 8 или 12.

```css
--s1: 4px;  --s2: 8px;  --s3: 12px;  --s4: 16px;  --s5: 24px;
```

| Значение | Чем задаётся |
|---|---|
| **4** (`--s1`) | внутренний отступ контейнера меню; зазор между заголовком дня и первой строкой; поля разделителя в меню |
| **8** (`--s2`) | зазор между элементами в шапке; горизонтальный отступ внутри строки записи; отступ заголовка «МИКРОФОН» от полей под ним; выход строки записи за поля списка (`margin: 2px -8px`) |
| **12** (`--s3`) | вертикальный отступ шапки; внутренний отступ панели «идёт запись»; отступ баннера снизу; нижний отступ закреплённой зоны |
| **16** (`--s4`) | боковые поля всего окна — шапки, закреплённой зоны, списка и настроек; нижний отступ списка |
| **24** (`--s5`) | отбивка заголовка дня от предыдущей группы; отбивка заголовка раздела настроек; отступ подвала сверху |

Значения меньше шкалы допустимы только внутри одного компонента, где они —
часть его рисунка, а не ритма экрана: `padding: 7px 8px` у строки записи,
`gap: 9px` и `10px` внутри строки, `margin-top: 1px` у мета-строки. Это
подгонка под оптический центр, а не новые ступени шкалы.

## 1.3 Скругления

```css
--r-sm: 6px;  --r-md: 8px;  --r-lg: 10px;
```

| Радиус | Что |
|---|---|
| **6** (`--r-sm`) | поля ввода, выпадашки, мелкие кнопки: иконка в шапке, `button.sec`, «⋯», пункты меню |
| **8** (`--r-md`) | строка списка, контейнер меню |
| **10** (`--r-lg`) | крупные кнопки (кнопка записи), баннеры, панель «идёт запись», карточки |

Отдельные значения вне шкалы — только там, где элемент вложен в скруглённый
контейнер и обязан повторить его форму изнутри: нижние углы `.note` внутри
карточки — `7px` (радиус карточки минус толщина рамки), аватар записи — `9px`,
всплывашка — `14px` и `11px` у её меню (это отдельное окно поверх системы, у
него своя, более мягкая пластика). Рамка окна в макете — `12px`, в настоящем
приложении её рисует система.

## 1.4 Текст

Основной шрифт — `system-ui, "Segoe UI", sans-serif`, базовая строка `14px/1.45`.

| Размер | Что | Начертание |
|---|---|---|
| **16** | заголовок экрана — «Записи», «Настройки» | 600, `letter-spacing: -.01em` |
| **15** | главная кнопка «Начать запись» | 600 |
| **14** | название записи, подпись «Запись идёт», таймер | 400 / 600 у подписи |
| **13** | пункты меню, `button.sec`, поля ввода, текст баннера, заголовок всплывашки | 400, 600 у заголовка |
| **12–13** | второстепенное: мета-строка записи, время справа, подсказки в настройках, «✓ Сохранено». Текст внутри карточки предупреждения — `12.5px` | 400 |
| **11** | заголовки дней («СЕГОДНЯ»), заголовки разделов настроек, подвал | 600 у заголовков, `text-transform: uppercase`, `letter-spacing: .07em` |
| **10** | подписи делений шкалы дБ, если шкала остаётся | 400, `--mono` |

### Моноширинный шрифт — только там, где важен символ

`--mono` остаётся **исключительно** для имён файлов и полей ввода: человек ждёт
ровно те символы, что лежат на диске. Там же обязательно
`font-variant-ligatures: none` — 0xProto склеивает `->` и `==` в один глиф.

**Так:** имя папки в подвале меню `2026-07-17_14-30_zoom`, поле «Адрес сервера»,
поле «Ключ доступа», поле переименования.

**Не так:** название встречи, мета-строка, время, таймер, заголовки дней. Всё это
теперь обычным шрифтом — это речь, а не данные.

Числа, которые меняются на месте и не должны дёргать соседей —
`font-variant-numeric: tabular-nums`: таймер записи, время встречи справа
в строке.

## 1.5 Иконки

- Набор — **[Lucide](https://lucide.dev)** (лицензия ISC). Только инлайновым SVG,
  скопированным в разметку: CSP не даст подключить библиотеку.
- Единые атрибуты контура: `fill="none" stroke="currentColor" stroke-width="1.8"
  stroke-linecap="round" stroke-linejoin="round"`. Толщина `1.7` у шестерёнки
  в шапке и `1.9` у стрелки «назад» и иконок дорожек — подгонка под размер.
- Цвет — всегда `currentColor`, чтобы иконка меняла цвет вместе с текстом
  родителя.
- Размеры: 17 в шапке · 15–16 внутри строки и всплывашки · 14 в пунктах меню ·
  13 у подписей дорожек · 11–12 внутри кнопок · 34 в пустом состоянии.

### Логотипы источников

Три фирменных логотипа — контуры из **[Simple Icons](https://simpleicons.org)**,
белым по фирменному фону:

| Источник | Фон плашки |
|---|---|
| Zoom | `#0B5CFF` |
| Microsoft Teams | `#6264A7` |
| Slack | `#4A154B` |

У логотипа плашка без рамки (`border-color: transparent`), у всего остального —
`--card` с рамкой `--line`.

**Неопознанный источник — значок микрофона из Lucide**, `--muted` на фоне
`--card`. Не буква, не вопросительный знак, не пустое место.

**Discord опознаётся, но своего знака пока не имеет.** Приложение слышит его
наравне с остальными (`src/detector/macos.rs`, `KNOWN_MEETING_PROCESSES`), а
рисуют его два окна по-разному, и это осознанная незаконченность, а не сбой:

| Где | Что видно | Почему |
|---|---|---|
| всплывашка (`ui/ask.js`) | буква «D» белым на `#5865F2` | плашка там 38×38 и всегда одна: пустой микрофон рядом с именем «Discord» читался бы как «не узнали» |
| строка списка (`ui/main.js`) | значок микрофона | в списке рядом стоят три настоящих логотипа, и буква среди них выглядит как недоделка |

Чужой логотип, нарисованный по памяти, — это не логотип, поэтому ни один из
вариантов не выдумывает знак. Свести оба к одному — решение владелицы,
см. раздел 6.

# 2. Компоненты

Все ссылки — на [`docs/mockups/layout-a.html`](mockups/layout-a.html); в скобках
указано состояние в левой панели макета, на котором компонент видно.

## Каркас окна

Три зоны сверху вниз, `display: flex; flex-direction: column; height: 100%`:

```
┌──────────────────────────────────────────┐
│ .head     Записи                    ⚙︎   │  flex: none
├──────────────────────────────────────────┤
│ .pinned   [баннер, если есть]            │  flex: none
│           [кнопка записи / панель]       │  граница снизу
├──────────────────────────────────────────┤
│ .body     СЕГОДНЯ                        │  flex: 1
│           ▢ Zoom            10:00–10:40  │  overflow-y: auto
│           ▢ Разбор метрик   14:30–15:05  │
│           …                              │
└──────────────────────────────────────────┘
```

Кнопка записи и панель «идёт запись» **никогда не уезжают за прокрутку** — они
в `.pinned`. Прокручивается только список. Полоса прокрутки — 8px, ползунок
`--line`, радиус 4.

## 2.1 Шапка (`.head`) — состояние «Покой»

**Из чего:** заголовок экрана `<h1>` 16px/600 (`flex: 1`) и кнопки-иконки 30×30.
Отступы `12px 16px`, зазор 8.

На экране записей: слева заголовок «Записи», справа шестерёнка «Настройки».
На экране настроек порядок меняется: слева стрелка «Назад», за ней заголовок
«Настройки». Стрелка стоит первой, потому что читают слева направо, а назад
уходят из левого верхнего угла.

**Состояния кнопки-иконки:**

| Состояние | Что видно |
|---|---|
| покой | иконка `--muted`, фон и рамка прозрачные |
| наведение | фон `--hover`, иконка `--fg` |
| фокус с клавиатуры | `outline: 2px solid var(--accent); outline-offset: 1px` |

У каждой кнопки-иконки обязательны `aria-label` и `title` — без текста рядом
иначе непонятно, что это.

## 2.2 Кнопка записи (`.record`) — «Покой»

**Из чего:** во всю ширину, высота 52, радиус 10, фон `--accent`, текст
`--on-accent` 15px/600, слева залитый круг 15px. Живёт в `.pinned`.

| Состояние | Что видно |
|---|---|
| покой | сплошная акцентная плашка |
| наведение | `filter: brightness(1.08)` — светлеет целиком, цвет не подменяется |
| фокус | `outline: 2px solid var(--fg); outline-offset: 2px` — контур светлый, а не акцентный: акцент на акценте не виден |
| нажата, команда ушла | `disabled`, `opacity: .5`, `cursor: default`, подпись «Начинаю…» |
| не получилось | кнопка возвращается в покой, ошибка — прямо под ней (см. правило 5) |

Состояний «нажата» и «не получилось» в макете нет — они заданы каноном, потому
что этого требуют правила 4 и 6.

## 2.3 Панель «идёт запись» (`.recording`) — «Идёт запись»

Заменяет кнопку записи в том же месте `.pinned`. Не появляется под ней и не
сдвигает список.

**Из чего:** рамка `--line`, радиус 10, фон `--card`, отступ 12.

1. **Верхняя строка** (зазор 10): красная точка 8px, пульсирует
   `2s ease-in-out infinite` от `opacity: 1` до `.3` · подпись «Запись идёт»
   14px/600 (`flex: 1`) · таймер `04:12` 14px `--muted` `tabular-nums` ·
   кнопка `button.sec` «Остановить» с залитым квадратом 11px.
2. **Два метра уровня** (`.mtr`, зазор 9, отступ сверху 9): слева иконка 16px
   `--muted` с `cursor: help` и подсказкой, справа метр `.disc.sm` во всю
   оставшуюся ширину.
   - микрофон → `title="Ваш микрофон"`
   - динамик → `title="Звук системы — то, что слышно от собеседников"`

Подписей «Вы» и «Система» в панели нет — только иконки: в 460 пикселях подпись
съедает треть метра. Полные слова стоят в настройках, где место есть.

**Состояния:**

| Состояние | Что видно |
|---|---|
| идёт | как описано выше |
| остановка отправлена | кнопка `disabled`, подпись «Останавливаю…», точка перестаёт пульсировать |
| системный звук не пишется | второй метр остаётся на месте и стоит на нуле, над кнопкой записи висит баннер (2.7). Метр не прячется — исчезнувшая дорожка читается как «всё хорошо» |

## 2.4 Строка записи (`.rec`) — «Покой»

Основной элемент экрана. Строка выходит за поля списка на 8 пикселей в каждую
сторону (`margin: 2px -8px`), поэтому подсветка под курсором доходит до краёв
окна, а текст остаётся на общей сетке.

**Из чего** (`.main`, зазор 10, отступ `7px 8px`):

1. **Плашка источника** `.ava` 34×34, радиус 9 — логотип или микрофон (1.5).
2. **Колонка** (`flex: 1; min-width: 0`):
   - `.title` — название встречи, 14px, обрезается многоточием;
   - `.sub` — мета-строка 12px `--muted`, обрезается многоточием.
3. **Правый блок** `.right` шириной 82 и высотой 26 — в нём наложены друг на
   друга время и кнопка «⋯».

**Что меняется по наведению и по фокусу** (`.rec:hover`, `.rec:focus-within` —
всегда парой):

| Элемент | Покой | Наведение / фокус |
|---|---|---|
| фон строки | прозрачный | `--hover` |
| время справа (`.time`) | видно | `opacity: 0` |
| кнопка «⋯» (`.dots`) | `opacity: 0`, `pointer-events: none` | `opacity: 1`, `pointer-events: auto` |
| хвост мета-строки (`.sub .more`) | `opacity: 0` | `opacity: 1` |

Сама кнопка «⋯» — 26×26, радиус 6, иконка `--muted`; под курсором иконка
становится `--fg`, а фон — `rgba(0,0,0,.25)`, чтобы читалась поверх уже
подсвеченной строки. Фокус — `outline: 2px solid var(--accent)`.

Переход — `.12s`. Время и «⋯» лежат в одной позиции абсолютом, поэтому строка
не дёргается. Ни один из этих элементов не скрыт через `display: none` — иначе
до «⋯» не добраться табом (правило 3).

**Состояния строки:**

| Состояние | Мета-строка | Что ещё |
|---|---|---|
| обычная | `40 мин` + под наведением ` · 12 МБ` | — |
| расшифровка готова | `35 мин` + под наведением ` · 10 МБ · расшифровка готова` | — |
| расшифровка идёт | `Расшифровываю…` | полоска `.prog` под мета-строкой |
| в очереди | `В очереди №2` | полоски нет — ждать нечего показывать |
| предупреждение | длительность и вес | карточка `.rec.card` (2.5) |
| не получилось | длительность и вес | карточка `.rec.card` с текстом ошибки и кнопкой «Попробовать снова» |

**Полоска прогресса `.prog`:** высота 3, радиус 2, дорожка `--line`, бегунок
`--accent` шириной 36%, едет `1.5s ease-in-out infinite`. Она неопределённая —
сервер не сообщает процент, и врать процентом нельзя.

**Заголовок дня** (`.day`): 11px/600 `--muted`, uppercase, `letter-spacing: .07em`,
отбивка `24px` сверху и `4px` снизу. У первого заголовка сверху `12px` — он не
отбивается от пустоты.

## 2.5 Карточка предупреждения (`.rec.card`) — «Не получилось расшифровать»

Та же строка записи, но обведённая и с приклеенным снизу текстом. Появляется,
когда с записью что-то не так и человек должен это увидеть **не наводя мышь**.

**Из чего:** рамка 1px `--warn`, радиус 8, отбивка `8px` сверху и снизу вместо
обычных `2px` — карточка отделяется от соседей. Внутри:

1. `.main` — обычная строка записи, отступ `8px 9px`;
2. `.note` — плашка снизу: фон `rgba(224,175,104,.10)`, верхняя граница
   `rgba(224,175,104,.28)`, текст `--warn` 12.5px/1.45, отступ `9px 11px`,
   нижние углы 7px. Внутри: иконка 15px слева, справа заголовок `<b>` 600
   отдельной строкой и объяснение под ним.

**Состояния** — карточка одна, наполнение разное:

| Случай | Иконка | Заголовок | Объяснение | Действие |
|---|---|---|---|---|
| собеседников не слышно | перечёркнутый микрофон | «Собеседников не слышно» | «Записан только ваш микрофон. Скорее всего, не было доступа к звуку системы.» | нет — чинить нечего, запись уже сделана |
| вас слышно тише | перечёркнутый микрофон | «Вас слышно заметно тише» | «Ваш микрофон записался намного тише собеседников — расшифровка может пропустить ваши реплики.» | нет |
| расшифровка не получилась | круг с восклицанием | «Расшифровка не получилась» | «Сервер не ответил. Запись цела — можно попробовать ещё раз или проверить адрес в настройках.» | ссылка «Попробовать снова» |

**Кнопка-ссылка внутри карточки** (`.act`): 12.5px, без фона и рамки,
подчёркивание `--muted` с отступом 3px. Наведение — цвет и подчёркивание
`--accent`. Фокус — `outline: 2px solid var(--accent)`.

Карточка ошибки использует те же `--warn`-цвета, что и предупреждение: запись
цела, потерь нет, красным пугать не за что. `--error` остаётся для «запись
не работает».

## 2.6 Меню «⋯» (`.menu`) — «Меню — обычная запись» и соседние состояния

Открывается по кнопке «⋯» в строке. Пока меню открыто, строка остаётся
подсвеченной, а «⋯» — видимой.

**Из чего:** абсолютом от строки (`right: 4px; top: 38px`), ширина от 186,
фон `--card`, рамка `--line`, радиус 8, внутренний отступ 4, тень
`0 12px 32px rgba(0,0,0,.55)`.

Пункт: иконка 14px + подпись 13px, отступ `7px 9px`, радиус 6, зазор 9.
Наведение и фокус — фон `--hover`. Разделитель `.sep` — 1px `--line` с полями
`4px`. Внизу — `small` 11px `--muted` с контекстом: имя папки записи или
пояснение, почему пункт недоступен.

**Три состава — по тому, зачем меню открывают** (правило 2):

| Состояние записи | Пункты сверху вниз | Подвал |
|---|---|---|
| обычная | Переименовать · Расшифровать встречу · — · Показать файлы | имя папки |
| расшифрована | **Открыть расшифровку** · Переименовать · — · Расшифровать заново · Показать файлы | имя папки |
| расшифровка идёт | Переименовать · — · Отменить расшифровку · Показать файлы | «Расшифровка уже идёт» |

Всё, что отменяет или переделывает уже сделанное, стоит **под разделителем**,
даже если это самый вероятный клик. Первый пункт — самое частое безобидное
действие.

## 2.7 Баннер (`.banner`) — «Нет системного звука»

Постоянное сообщение о том, что приложение работает не полностью. Живёт в
`.pinned` **над** кнопкой записи, висит до перезапуска.

**Из чего:** рамка 1px `--warn`, радиус 10, текст `--warn` 13px/1.4, отступ
`10px 12px`, отбивка снизу 12. Справа — `button.sec`, `flex: none`, чтобы не
ужиматься до многоточия.

Ровно два факта и кнопка: **что не работает** и **что от этого сломалось**.
Всё остальное — куда жать, что перезапускать, какая была техническая причина —
в `title` баннера. Текст читают один раз, а видят каждый день.

**Состояния:** есть / нет. Промежуточных нет — баннер не сворачивается и не
закрывается крестиком: проблема никуда не делась.

## 2.7-бис Строка взвода (`.armed`) — «Взвод»

Приложение услышало встречу и ждёт ответа. Вопрос при этом задаёт всплывашка
(2.8) — **в окне вопроса нет**, иначе один и тот же вопрос висел бы в двух
местах сразу (правило 3.7). В окне остаётся только состояние.

Поэтому это **не баннер**: рамки нет, фона нет. Рамка поставила бы строку в один
ряд с сообщениями о поломках выше, а ничего не сломалось.

**Из чего:** строка `display: flex`, зазор 10, отбивка снизу 12, боковой отступ
1 — вровень с рамкой кнопки под ней.

- слева `<span>` 13px/1.4 `--muted`, обрезается многоточием: «Похоже, встреча
  в Zoom». Без опознанной звонилки — просто «Похоже, встреча». Те же слова, что
  в подсказке трея (`tray.rs`, `ARMED`);
- справа `button.sec` «Не записывать».

**«Да» отдельной кнопкой здесь нет.** Его говорит акцентная кнопка записи прямо
под строкой: во взводе `toggle` доходит до машины как `ManualStart`, то есть как
подтверждение, и предзапись не теряется (`audio.rs`, `ctl_to_event`). Вторая
кнопка «Записать» рядом с ней была бы двумя словами про одно действие.

**«Нет» здесь есть, и это единственное место, где он есть.** Во всплывашке
отказ — это смахивание, а сама она уезжает через семь секунд; в трее во взводе
пункт один и он тоже утвердительный. Убрать «Не записывать» отсюда значит
оставить взвод без отказа вообще.

Строка помечена `role="status"`, и текст в неё ставится в момент перехода во
взвод, а не заранее: живая область озвучивает смену текста, а не то, что готовый
текст стал видимым.

| Состояние | Что видно |
|---|---|
| взвод | строка + кнопка «Не записывать», ниже обычная кнопка записи |
| ответили или встреча кончилась | слот схлопывается, строка исчезает |
| фатальная ошибка во взводе | кнопка записи погашена, «Не записывать» остаётся живой |

## 2.8 Всплывашка «Записать встречу?» — «Всплывашка»

Отдельное окно поверх всех остальных, у верхнего правого угла экрана. Своё окно,
а не часть главного: вопрос приходит ровно тогда, когда человек заговорил в
звонке, и окно 460×640 в этот момент закрыло бы собеседника и забрало
клавиатуру. Не системный тост: кнопок в системном уведомлении нет
(`tauri-plugin-notification` не прокидывает actions), а на macOS его ещё и
глушит «Не беспокоить» — ровно во время звонка. Тост при этом остаётся: он
нужен там, где всплывашки не видно (полноэкранный режим на другом мониторе).

**Разметка живёт отдельно** — `ui/ask.html` + `ui/ask.js`, не в `index.html`.

**Токены приложения здесь не действуют.** Это окно лежит поверх чужих окон и
должно читаться как часть системы, а не как кусок приложения, всплывший наружу.
Пропорции сняты с системного уведомления macOS.

**Из чего** (ширина плашки 380, зазор 11, отступ 12, радиус 18):

- фон `rgba(38,38,41,.97)`. Плотный, а не полупрозрачный с размытием:
  `backdrop-filter` видит только саму страницу, а под ней прозрачное окно, —
  живого размытия добиться нельзя, и на глаз плотный фон совпадает с тёмным
  системным материалом;
- тень `0 8px 20px rgba(0,0,0,.38)` и волосяная линия внутрь
  `0 0 0 .5px rgba(255,255,255,.10) inset`;
- плашка источника 38×38, радиус 9. Настоящий знак есть только у Zoom;
  остальным буква на фирменном цвете (1.5);
- заголовок «Записать встречу?» 13px/600 `rgba(255,255,255,.96)`, под ним
  источник («Zoom») 12px `rgba(255,255,255,.56)`;
- кнопка `.go` «Записать» — светлое стекло `rgba(255,255,255,.15)`, радиус 8,
  отступ `7px 14px`. Не акцентная заливка: цветная кнопка читалась бы как
  веб-кнопка, наклеенная поверх системного окна;
- `.life` — линия жизни 2px по нижнему краю, `rgba(255,255,255,.30)`, уезжает
  от 100% к 0 за 7 секунд.

**Движение — пружина, а не кривая.** Плашка выезжает сверху и уходит вбок на
критически затухающей пружине, считаемой от текущего положения: жест можно
перехватить на полпути и развернуть без скачка. Уходит она всегда вправо — и
когда смахнули, и когда вышло время, и когда ответили: так делают системные
уведомления macOS, и один и тот же исход выглядит одинаково, чем бы он ни был
вызван.

**Отказ — смахивание вправо**, пальцами по трекпаду или мышью. Решение
принимается по скорости, а не по пути: короткий быстрый флик тоже смахивает.
Подсказка «Смахните вправо двумя пальцами» — только в макете, в живом
приложении её нет.

**Состояния:**

| Состояние | Что происходит |
|---|---|
| показана | линия жизни уезжает, через 7 секунд плашка уходит вбок |
| наведение | линия жизни **останавливается** и светлеет — пока мышь на плашке, вопрос не уезжает |
| вышло время | плашка уходит, но это **не ответ**: взвод остаётся, ответить можно в окне (2.7-бис) и в трее |
| смахнули вправо | ответ «не записывать»: машина уходит из взвода, вопрос гаснет везде |
| нажали «Записать» | плашка уходит сразу, не дожидаясь подтверждения: пауза между действием и откликом — это ровно то, из-за чего интерфейс перестаёт ощущаться прямым |

**Наведение считает Rust, а не CSS.** Окно принадлежит неактивному приложению, а
таким окнам macOS движений мыши не шлёт: ни `:hover`, ни `mouseenter` здесь не
срабатывают никогда. Положение курсора отслеживает `audio.rs` и присылает
готовым событием `hover`.

**С клавиатуры всплывашка недостижима, и это осознанно:** окно
`focusable: false`, чтобы клавиатура осталась у звонилки. Поэтому ответить с
клавиатуры можно только в главном окне — см. 2.7-бис и правило 3.3.

## 2.9 Метр уровня (`.disc`) — «Идёт запись» и «Настройки»

Сегментированная полоска: маска `repeating-linear-gradient(to right, #000 0 3px,
transparent 3px 6px)` режет её на штрихи 3px через 3px.

**Из чего:** дорожка `.t` цвета `--line` и заливка `.f` поверх неё. Заливка —
**неподвижный градиент**, обрезаемый справа через
`clip-path: inset(0 calc(100% - var(--level)) 0 0)`, переход `.12s linear`.

```
0%                            70%        90%     100%
├──────────── зелёный ─────────┼─ жёлтый ─┼─ красный ─┤
      норма                    громко      перегруз
-60 дБ                       -18 дБ     -6 дБ    0 дБ
```

Проценты не на глаз: шкала линейна по децибелам от `МЕТР_ПОЛ_ДБ` = -60 до 0, и
70% с 90% — это ровно -18 дБ и -6 дБ.

**Пиковый маркер** (`.disc > b`) — сплошная линия 2px цвета `--fg` поверх
штрихов, держит недавний максимум и сползает к текущему уровню. Пока сигнала не
было ни разу, он невидим: на пустом метре линия у нулевой отметки читалась бы
как показание.

Градиент именно неподвижный, а не растягивающийся вместе с заливкой: иначе цвет
зависел бы от текущей громкости, а не от абсолютного уровня — и тихая речь, и
перегруз красились бы одинаково.

**Два размера:** 12px в настройках, 8px (`.disc.sm`) в панели «идёт запись».

**Подписи:** в настройках слева от метра — `em` шириной 96 с иконкой 13px и
словом: **«Вы»** и **«Система»**. В панели записи — только иконка с подсказкой.

**Числа в децибелах человеку не показываются** (см. раздел 4). Вместо шкалы —
одна подсказка под метрами: «Говорите обычным голосом: полоска должна доходить
примерно до конца зелёного и не залезать в красное.»

Ориентир — **конец зелёного, а не середина**. Середина полоски это -30 дБ,
то есть шёпот; нормальная речь на здоровом уровне записи даёт -18…-9 дБ, то есть
70–85% и уже задевает жёлтое. Подсказка про середину звала бы говорить втрое
тише, чем надо, — и на экране это видно: при обычном голосе полоска стоит явно
за серединой.

**Состояния:** сигнал есть / сигнала нет (полоска стоит на нуле, дорожка видна).
Метр никогда не прячется — пустая дорожка и есть сообщение «тут тихо».

## 2.10 Остальное на экране

**Пустой список** (`.empty`, состояние «Пустой список»): по центру, отступ
`60px 24px`, микрофон 34px при `opacity: .45`, заголовок 14px/600 `--fg`
«Записей пока нет», под ним 13px/1.55 `--muted`: «Приложение само предложит
записать, когда услышит звонок. Или нажмите „Начать запись“.» Пустое состояние
всегда говорит, что делать дальше.

**Загрузка списка** (`.sk`, состояние «Загрузка списка»): три серых силуэта,
повторяющих настоящую строку — плашка 34×34, две полоски текста разной ширины,
время справа. Пульсация `opacity .4 ↔ .85` за `1.4s`. Силуэт повторяет реальную
строку, чтобы список не прыгал, когда данные приедут.

**Поля в настройках:** 13px, отступ `7px 8px`, радиус 6, рамка `--line`, фон
`--bg` (не `transparent` — иначе нативный попап выпадашки рисуется светлым и
тёмные пункты в нём пропадают). У выпадашки родная стрелка убрана
(`appearance: none`) и заменена шевроном Lucide — **отдельным инлайновым
`<svg class="chev">`** поверх поля, а не картинкой в `background-image`: иконки
в этом приложении только инлайновые (1.5). Клики сквозь стрелку проходят
(`pointer-events: none`), справа у поля `padding-right: 30px`. Фокус — `outline: 2px solid var(--accent)`.

**Подтверждение сохранения:** «✓ Сохранено» 12px `--good` под полем. Не тост,
не модалка.

**Подвал** (`.foot`): 11px `--muted` по центру, отбивка 24 сверху. Это кнопка,
а не `<a href>`: обычная ссылка в вебвью Tauri открылась бы внутри окна вместо
системного браузера.

# 3. Правила

Семь правил. Каждое нарушение видно глазами на макете, поэтому проверяются они
не тестами, а взглядом на экран.

## 3.1 Предупреждение о состоянии записи никогда не прячется под наведение

Под наведение уходит только нейтральное: вес файла, отметка «расшифровка
готова». Всё, из-за чего запись получилась хуже, видно сразу.

**Так**

```html
<li class="rec card">
  <div class="main">…<div class="sub">25 мин<span class="more"> · 7 МБ</span></div>…</div>
  <div class="note"><b>Собеседников не слышно</b>Записан только ваш микрофон…</div>
</li>
```

Вес — под наведением. «Собеседников не слышно» — карточкой, всегда.

**Не так**

```html
<div class="sub">25 мин<span class="more"> · 7 МБ · только ваш микрофон</span></div>
```

Человек пролистал список и уверен, что все шесть записей в порядке.

## 3.2 Первым пунктом меню стоит то, зачем человек его открыл

Состав меню зависит от состояния записи. Одинакового меню на все случаи нет.

**Так** — у расшифрованной записи первым идёт «Открыть расшифровку»; у обычной
первым идёт «Переименовать», а «Расшифровать встречу» — вторым.

**Не так** — один и тот же список из пяти пунктов везде, и «Открыть расшифровку»
четвёртым, между «Переименовать» и «Показать файлы».

Оговорка: отменяющее и переделывающее («Отменить расшифровку», «Расшифровать
заново») уходит под разделитель, даже когда это самый вероятный клик. Первый
пункт — самое частое **безобидное** действие.

## 3.3 Всё, что появляется по наведению, достижимо с клавиатуры

`:hover` и `:focus-within` пишутся **одним правилом, всегда парой**. Скрывать
элемент через `display: none` или `visibility: hidden` нельзя — он выпадает из
обхода табом.

**Так**

```css
.rec:hover, .rec:focus-within { background: var(--hover); }
.rec:hover .dots, .rec:focus-within .dots { opacity: 1; pointer-events: auto; }
```

**Не так**

```css
.rec:hover .dots { opacity: 1; }        /* табом до «⋯» не добраться */
.dots { display: none; }
.rec:hover .dots { display: flex; }     /* кнопки нет в дереве фокуса */
```

Прецеденты в коде: `.rec:hover, .rec:focus-within` — подсветка строки, вес файла,
кнопка «⋯». У кнопок, которые ничего не раскрывают, пара другая: `:hover` меняет
вид, `:focus-visible` рисует контур (`button.sec`, `.icon-btn`, `.record`,
`.dots button`, `button.link`).

Из этого правила следует и то, где живёт ответ на вопрос «записать встречу?».
Всплывашка клавиатуру не берёт принципиально (2.8), поэтому и «да», и «нет»
обязаны быть достижимы в главном окне — иначе вопрос без мыши не отвечается
вовсе.

## 3.4 У каждого асинхронного действия есть «идёт» и «не получилось»

Три состояния обязательны: покой → идёт → получилось / не получилось. Двух не
бывает.

**Так** — нажали «Расшифровать встречу»: мета-строка сменилась на
«Расшифровываю…», под ней поехала полоска. Сервер не ответил — на её месте
карточка «Расшифровка не получилась» с кнопкой «Попробовать снова».

**Не так** — нажали «Расшифровать встречу», меню закрылось, строка не
изменилась. Через минуту где-то появился файл. Или не появился.

Отдельно: очередь — тоже состояние. Первая запись «Расшифровывается», остальные
«В очереди №2», «В очереди №3». Без этого три одинаково замерших строки читаются
как три поломки.

## 3.5 Ошибка показывается там, где сломалось

**Так** — расшифровка отвалилась у записи от 16:00: карточка приклеена к строке
этой записи.

**Не так** — общая строка `#err` под списком: «Сервер не ответил». Какая из шести
записей? Непонятно, и через десять секунд строка исчезнет.

Единственное исключение — фатальная ошибка, после которой не работает вообще
ничего: она показывается у кнопки записи, потому что сломалась именно она.

## 3.6 Кнопка гаснет по клику, а не когда придёт ответ

**Так**

```js
кнопка.disabled = true;
кнопка.textContent = "Начинаю…";
try { await invoke("start"); } finally { кнопка.disabled = false; }
```

**Не так**

```js
await invoke("start");
кнопка.disabled = true;   // между кликом и этой строкой прошла секунда
```

За эту секунду по кнопке успевают нажать трижды.

То же самое относится ко всему, что уходит в бэкенд: «Остановить», «Расшифровать
встречу», «Проверить» в настройках, «Записать» во всплывашке.

## 3.7 Один вопрос задаётся ровно в одном месте

У приложения к человеку один вопрос — «записать эту встречу?». Задаёт его
всплывашка, и больше никто.

**Так** — всплывашка спрашивает; окно, если его открыть, говорит «Похоже,
встреча в Zoom» и держит «Не записывать»; трей мигает и предлагает «Записать эту
встречу».

**Не так** — всплывашка спрашивает «Записать встречу?» с кнопкой «Записать», и
одновременно в окне висит баннер «Записать встречу?» с кнопками «Записать» и
«Не записывать». Человек не понимает, одно это дело или два, и что будет, если
ответить в обоих местах.

Разница между «задать вопрос» и «показать состояние» вся в словах: вопрос
кончается знаком вопроса и стоит в собственной рамке, состояние — обычная строка
без рамки. Второе можно показывать где угодно, первое — только в одном месте.

Оговорка: **потерять действие при этом нельзя**. Если ответить где-то было
можно, а после переноса вопроса стало нельзя — правило нарушено ровно так же,
как и двоением. Поэтому «Не записывать» из окна не ушло: во всплывашке отказ —
это смахивание, а она уезжает через семь секунд.

# 4. Как разговаривает приложение

## 4.1 Ошибка

Короткая, без технического жаргона, и **всегда сказано, что делать дальше**.
Порядок один: что случилось → что от этого сломалось → что сделать.

Если делать нечего (запись уже сделана, чинить нечего) — так и говорим, не
придумывая ложное действие.

## 4.2 Словарь

| Говорим | Не говорим |
|---|---|
| **Вы** | mic, микрофонная дорожка |
| **Система** | system, системная дорожка, loopback |
| **расшифровка**, **расшифровать** | транскрипция, транскрибировать, STT |
| **адрес сервера** | URL шлюза, endpoint, хост |
| **ключ доступа** | ключ, токен, API-key |
| **запись** (файл встречи) | сессия, запись сессии |
| **звук системы** | вывод, output, loopback-поток |

**Запрещены в интерфейсе:** шлюз · эндпоинт · дорожка (в значении аудиодорожки —
для человека это «вы» и «система») · дБ · транскрибировать.

Про децибелы отдельно: метр уровня остаётся, шкала с числами уходит. Вместо
«−18 дБ» человеку говорится «полоска должна доходить примерно до конца зелёного
и не залезать в красное» (2.9 — почему до конца зелёного, а не до середины).

## 4.3 Сырые сообщения из движка человеку не показываются

На экране — короткая человеческая строка. Техническая причина — в `title`,
то есть доступна тому, кто её ищет, и не мозолит глаза остальным.

**Так**

```js
$("nosysaudio-text").textContent = "Системный звук не пишется — только ваш микрофон.";
el.title = `Причина отказа: ${причина}`;
```

**Не так**

```js
показать_ошибку(String(e));   // «Failed to build input stream: DeviceNotAvailable»
```

## 4.4 Было / стало

Разбор четырёх настоящих текстов. Колонка «стало» — норма канона; переписываются
эти строки в ветке `feat/ui-copy`, не здесь.

### `ui/main.js:52` — фатальная ошибка

**Было**

```js
показать_ошибку(`${причина} — запись работать не будет`);
```

Причина приходит из бэкенда как есть. Самая частая — `status::DEAD`:
«аудио-поток остановился: запись не работает, перезапустите приложение». На
экране получается:

> аудио-поток остановился: запись не работает, перезапустите приложение — запись работать не будет

Хвост повторяет то, что уже сказано, «аудио-поток» — слово не из этого языка, и
строка висит внизу экрана, отдельно от кнопки, которую только что погасили.

**Стало**

> **Записывать сейчас не получится.** Перезапустите приложение.

На месте кнопки записи, не в общей строке (правило 3.5). Полный текст причины —
в `title`.

### `ui/main.js:110-118` — баннер про системный звук

**Было**

> Системный звук не записывается — только микрофон. Автоопределение встреч не сработает.

**Стало** (текст из макета)

> Системный звук не пишется — только ваш микрофон. Встречи сами определяться не будут.

Что изменилось: «микрофон» → «ваш микрофон» — иначе непонятно, чей;
«Автоопределение встреч не сработает» → «Встречи сами определяться не будут» —
«автоопределение» человек не говорит.

Что осталось правильным и переносится как есть: два факта и кнопка, а маршрут
по настройкам и техническая причина — в `title` (`ui/main.js:113-116`).

### `src-tauri/src/audio.rs:117-121` — тост «Похоже, встреча»

**Было**

```rust
.title("Похоже, встреча")
.body(format!("{source} — записать? Ответьте в окне приложения."))
```

«Похоже, встреча» — не вопрос и не действие, по нему непонятно, чего от тебя
хотят. «Ответьте в окне приложения» — это извинение за то, что у системного
тоста нет кнопок.

**Стало** — собственная всплывашка (2.8), где кнопка есть:

> **Записать встречу?**
> Zoom  · [ Записать ]

Строка «Ответьте в окне приложения» исчезает вместе с причиной, по которой она
была нужна. Сам тост при этом остаётся с тем же текстом заголовка: он нужен
там, где всплывашки не видно.

### `src-tauri/src/audio.rs:164-167` — «Пишется не тот микрофон»

**Было**

```rust
.title("Пишется не тот микрофон")
.body(format!("«{имя}» недоступен — запись идёт с системного по умолчанию."))
```

Заголовок звучит как обвинение и не говорит, что делать. «Системный по
умолчанию» — название настройки, а не объяснение.

**Стало**

> **Микрофон «Yeti Nano» недоступен**
> Пишу тем, что выбран в системе. Проверьте, подключён ли он, или выберите
> другой в настройках.

Сначала факт, потом что приложение сделало вместо этого, потом что можно сделать
человеку.

# 5. Проверить перед показом

Пробегитесь по списку, глядя на экран. Каждый пункт — правило выше.

- [ ] Ни одного значения отступа вне шкалы 4 / 8 / 12 / 16 / 24 в разметке экрана.
- [ ] Ни одного радиуса вне 6 / 8 / 10, кроме описанных исключений.
- [ ] `--mono` стоит только на именах файлов и полях ввода.
- [ ] Все иконки — инлайновый SVG с `stroke="currentColor"`.
- [ ] Каждое `:hover` имеет пару `:focus-within` или `:focus-visible`.
- [ ] Пройдено табом сверху вниз: до «⋯» в каждой строке можно добраться,
      контур фокуса виден на всех кнопках.
- [ ] У каждой кнопки, которая ходит в бэкенд, есть «идёт» и «не получилось».
- [ ] Кнопки гаснут по клику.
- [ ] Ни одной ошибки в общей строке внизу экрана.
- [ ] Ни одного предупреждения о качестве записи, спрятанного под наведение.
- [ ] Ни одного запрещённого слова: шлюз, эндпоинт, дорожка, дБ, транскрибировать.
- [ ] В каждом сообщении об ошибке сказано, что делать дальше.
- [ ] Горизонтальной прокрутки нет ни на одном состоянии, включая самое длинное
      имя устройства в настройках и длинное имя записи после переименования.
- [ ] Вопрос «записать встречу?» задаётся ровно в одном месте, и при этом ни
      «да», ни «нет» никуда не пропали (правило 3.7).
- [ ] Экран пройден табом целиком, включая настройки. То, что мышью можно, а
      клавиатурой нельзя, — либо ошибка, либо записано здесь как осознанное
      (единственное такое место — всплывашка, 2.8).

# 6. Чего в каноне нет

Сознательно не описано, потому что решения ещё не принято:

- **переключатель темы в интерфейсе.** Обе темы — светлая и тёмная — есть в
  токенах и следуют системной `prefers-color-scheme`, крючок `data-theme`
  на `<html>` работает, если проставить его руками; своего пункта в
  настройках для этого пока нет;
- поведение окна при изменении размера — окно фиксированное 460×640;
- звуки и уведомления в трее, кроме описанных;
- **плашка Discord.** Источник уже опознаётся, но своего знака у него нет, и
  два окна показывают его по-разному (1.5). Свести к одному — либо буква на
  фирменном цвете и в списке тоже, либо контур из Simple Icons в оба места;
- иконка Google Meet — источник ещё не опознаётся;
- **варианты ответа во всплывашке кроме «Записать».** В макете была стрелка с
  меню: «Не записывать» · «Записать только меня» · «Не спрашивать про Zoom
  сегодня». Собрано из этого только смахивание (= «не записывать»); двух
  оставшихся пунктов нет ни в интерфейсе, ни в бэкенде. Из макета они убраны,
  чтобы он не обещал несуществующего;
- **таймер записи в окне, открытом посреди встречи.** Снимок состояния
  (`get_state`) не отдаёт момент начала, поэтому таймер показывается только той
  записи, которую начали при открытом окне. Чинится в бэкенде, не здесь;
- **имя звонилки в строке взвода после перезагрузки окна.** Кто звонит, окно
  узнаёт из события `ask`, а оно приходит один раз. Открыли окно позже — строка
  честно говорит «Похоже, встреча», без имени: в снимке состояния источника нет.
  Тоже правится в бэкенде;
- экран самой расшифровки — его в этой итерации нет, «Открыть расшифровку»
  открывает файл системным способом.

Появилось новое решение — оно дописывается сюда, а не остаётся в чате.
