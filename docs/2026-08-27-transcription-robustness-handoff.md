# Передача работы: устойчивость транскрипции и Windows

Дата: 27.08.2026. Ветка: `docs/transcription-robustness`.
Спека: `docs/2026-08-27-transcription-robustness-and-windows-design.md`
План: `docs/2026-08-27-transcription-robustness-and-windows-plan.md`

Работа остановлена не по завершении, а потому что **проверять код стало нечем**.
Здесь всё, что нужно, чтобы продолжить с другой машины.

## Почему остановились

GitHub Actions на этом аккаунте перестал выдавать раннеры. Аннотация упавших
прогонов, дословно:

> The job was not started because recent account payments have failed or your
> spending limit needs to be increased.

Джобы падают за две секунды, не выполнив ни одного шага. Перезапуск даёт то же
самое.

**Не «локально проект не собирается в принципе» — так неточно, и это важно.**
Библиотека ядра (`cargo test -p meeting-recorder --lib`) под Linux собирается и
её тесты реально проходят нативно — 135 штук на момент этой правки. Не
собираются только бинарники и GUI-крейт: платформенные модули объявлены только
под Windows и macOS (`src/detector/mod.rs`, отсюда падает `meeting-recorder-cli`
— `recordings_root()` в `src/main.rs` под Linux не существует ни в одной ветке
`cfg`), а `reveal()` (`src-tauri/src/main.rs`) под Linux оставляет переменную
необъявленной — тоже ошибка компиляции, а не предупреждение, и от неё падает
`meeting-recorder-gui`. То есть CI был единственным доступным способом
проверить бинарники и GUI-крейт целиком — но не единственным способом
проверить хоть что-то: ядро и его тесты доступны локально всегда.

**Что делать:** либо починить биллинг (учтите: macOS-раннеры тарифицируются
10× минут, Windows 2× — именно они и съели квоту за семь прогонов), либо
продолжать на машине с macOS или Windows, где есть `cargo`.

### Обходной путь, уже настроенный на этой Linux-машине

Проект под Linux не собирается, но **кросс-компиляция под Windows работает** и
проверяет ровно те ветки кода, которые под Linux недостижимы. Настроено без
единого повышения прав: `apt-get download` не требует root, а `dpkg-deb -x`
разворачивает пакет в любой каталог.

```bash
export RUSTUP_HOME=/data/cypher-ai-lab/rust/rustup
export CARGO_HOME=/data/cypher-ai-lab/rust/cargo
export XWIN_CACHE_DIR=/data/cypher-ai-lab/rust/xwin
export CARGO_TARGET_DIR=/data/cypher-ai-lab/rust/mr-target
LLVM=/data/cypher-ai-lab/rust/llvm/root/usr/lib/llvm-18
export LD_LIBRARY_PATH="$LLVM/lib:/data/cypher-ai-lab/rust/llvm/root/usr/lib/x86_64-linux-gnu"
export PATH="$LLVM/bin:$CARGO_HOME/bin:$PATH"

cargo xwin check -p meeting-recorder     --target x86_64-pc-windows-msvc --all-targets
cargo xwin check -p meeting-recorder-gui --target x86_64-pc-windows-msvc --all-targets
```

Помимо rustup и `cargo-xwin` понадобились: `llvm-rc` — им `tauri-winres`
компилирует ресурсы Windows, иконку и манифест; `clang-cl` — им `cc-rs` собирает
C-зависимости под MSVC; и разделяемые библиотеки к ним. Пакеты `llvm-18`,
`clang-18`, `libclang-cpp18`, `libllvm18`, суммарно 65 МБ, распакованы в `/data`,
в системные пути не писалось ничего. Компонент `llvm-tools` от rustup тут НЕ
помогает: `llvm-rc` в него не входит — это была моя ошибка в первой попытке.

**Граница проверки: `cargo check` компилирует, но не запускает.** Wine на машине
нет. Тесты вроде `каталог_записей_выводится_из_профиля_пользователя` сверяются с
настоящим `%USERPROFILE%` и осмысленны только на живой Windows.

### Проверки, которые может сделать только человек

- **Раскладка всплывашки на Windows.** Шрифт `-apple-system, system-ui,
  "SF Pro Text"` при 13px в окне высотой 96 (`ui/ask.html:13`); на Windows это
  Segoe UI с другими метриками. Автотеста нет, проверяется зрением.
- **Живая расшифровка записи длиннее часа.** Это единственный способ увидеть,
  что потолка в 60 минут больше нет. Нужен доступ к шлюзу ai-lab.
- **Отмена при двух записях в очереди:** отменить идущую и убедиться, что
  вторая стартовала сразу. До задачи 10 она стартовать сразу НЕ будет —
  задача на шлюзе доживает и держит GPU.

## Решения, принятые по ходу

Каждое можно отменить; здесь они собраны, чтобы было что отменять.

1. **Отдельный git worktree не заводился** — работали в основном чекауте на
   фича-ветке. Лишние копии репозитория забивают корневой диск.
2. **Пуш, PR и мердж выносились владельцу.** Мердж редизайна сделан по прямому
   указанию, всё остальное — нет.
3. **Проверка Rust шла через CI, а не локально.** Исполнителям было запрещено
   запускать `cargo`; они писали код и тесты, прогон делал GitHub.
4. **README оставлен русским** (версия 0.2.0). Английский вариант с
   `prepare-public-release` не переносился: репозиторий приватный, публикация
   не планируется, весь код и документы русские. Текст не потерян, он в той
   ветке.
5. **`identifier: net.cypher-cloud.meeting-recorder` в `tauri.conf.json`
   не тронут**, хотя домен тот же, что вычищался из документов. От него
   зависит путь к каталогу настроек, и смена означает миграцию конфига у всех,
   кто уже поставил сборку. Отдельное решение, а не вычистка следов.
6. **Задача 11 заведена по ходу**, её в исходном плане не было — находка
   всплыла при вычистке личных путей.
7. **Rust-задачи остановлены, когда отвалился CI.** Писать дальше без единого
   способа скомпилировать значило бы копить непроверенную работу и выдавать её
   за сделанную.
