# Стенд состояний интерфейса

```sh
python3 docs/preview/serve.py      # http://127.0.0.1:3015/
python3 docs/preview/serve.py 3020 # если 3015 занят
```

Слева список состояний, справа окно ровно 460×640 — как настоящее. Внутри рамки
крутятся **настоящие** `ui/index.html`, `ui/main.js` и `ui/ask.html`: подменён
только слой, который в приложении отвечает Rust (`shim.js`). Разъедется вёрстка
в приложении — разъедется и здесь.

## Зачем он нужен

Половину состояний в живом приложении не вызвать, не сломав что-нибудь
по-настоящему: фатальную ошибку, отказ в захвате системного звука, очередь из
трёх расшифровок, первую загрузку списка, недоступный микрофон. Стенд показывает
их за один клик — и держит рядом крайние случаи, о которых иначе вспоминают
после релиза: самое длинное имя устройства, длинное имя после переименования.

## Чего он не показывает

Машины записи, прав macOS, трея и того, что бэкенд действительно шлёт эти
события в этом порядке. **Стенд не заменяет живое приложение** — перед показом
смотреть надо оба: стенд за полнотой состояний, приложение за правдой.

## Проверки перед показом

Чек-лист — в дизайн-каноне (`docs/2026-08-26-ui-design-system.md`, раздел 5).
Два пункта из него стенд считает сам:

```sh
# что вылезает за 460, где появилась горизонтальная прокрутка,
# что достижимо табом — по одной сцене
open "http://127.0.0.1:3015/__measure?s=longmic"   # ответ в заголовке вкладки
```

`/__shot?s=<сцена>` отдаёт ту же сцену без панели, кадром ровно 460×640 — под
`--screenshot` в headless-браузере, если нужны картинки для обсуждения.

## Как добавить состояние

1. Новая пара в `СЦЕНЫ` (`serve.py`) — ключ и человеческое название.
2. Ветка по этому ключу в `shim.js`: либо в `снимок` (если состояние приходит
   снимком из `get_state`), либо в блок «сцены, которые складываются из событий
   после старта» (если оно набирается событиями).

Данные списка тоже там — `СПИСОК` в `shim.js`.
